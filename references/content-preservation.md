# 默认文字保真

原文不改、视觉可调、附加文字有明确范围。AI选择强调与组件，程序负责核对；它不是文案润色模式。

## 基线与命令

基础Markdown直接作为基线，不重写成更“顺”的稿子。正文、原标题、小标题、数字、原话、标点、阅读顺序、链接、图片须保留。允许加粗、下划线、换行、卡片和列表的呈现转换。

```bash
python3 scripts/render.py article.json --source 原稿.md --theme all --out 新目录
```

Word/PDF/复杂Markdown先对照原文件无损整理为source.json，并人工核对图片、链接、表格、代码、脚注、编号、顺序，再整理article.json。source.json采用同一输入契约，但保留原始文字、不加编辑标签。记录原文件指纹、来源页码和未解决导入问题。报告会说明仅核对normalized-json，不能据此声称原文件自动无损。

```bash
python3 scripts/check_content.py 原稿.md article.json
python3 scripts/render.py article.json --source source.json --theme all --out 新目录
```

直接输入基础Markdown会自动以自己作为基线。JSON缺少--source默认报错；显式--allow-unverified仅供样式试排，报告不标记保真通过。不能用这个开关绕过正式交付的核对。

## 附加范围

1. 模板装饰：章节编号、相关英文标签、星形/箭头、组件内固定的提示标签；逐主题记录实际渲染的附加文字。它们不视作原文。
2. 作者区：已有作者和互动句沿用原文；未知作者可显示“作者姓名”“一句话介绍自己”，不显示`{{…}}`。原稿无互动句时可用已确认的“感谢阅读。欢迎留言分享你的看法。”。用户要求省略时省略。
3. 新增中文组件标题只允许“风险提醒”“补充说明”“行动建议”“虚构示例”“提示”“数据”。即使在这个范围内也要声明，不能默默排除。
4. 原文已有的标题、组件标题、署名不是附加，不得豁免核对。原文没有的新导读、新章节标题、新总结句默认不加。要改文案，应先取得用户对具体修改的同意，再另存确认后的基线；不允许任意声明“这是附加”跳过检查。

article.json的声明示例（索引必须匹配本篇实际块）：

```json
{
  "editorial_plan": {
    "allowed_additions": [
      {"path":"/blocks/3/title","text":"风险提醒","kind":"component_label"},
      {"path":"/blocks/9/name","text":"作者姓名","kind":"signature"},
      {"path":"/blocks/9/bio","text":"一句话介绍自己","kind":"signature"},
      {"path":"/blocks/9/cta","text":"感谢阅读。欢迎留言分享你的看法。","kind":"signature"}
    ]
  }
}
```

作者区使用小标识与两行文字并排、细线分隔，互动句为辅助小字；八主题按各自颜色适配。该形式不要求用户提供头像，不创建假图片。

## 核对范围与边界

- 原稿与语义稿：比较文字流与顺序，忽略普通正文空白和支持的强调标记；标点与文字不替换，代码块逐字符比较。另核对链接目标和图片内容指纹/网络URL。
- 分段和组件可以改变，所以不以段落数量或总字数作为通过标准。普通正文空白不在逐字保证范围内，代码不适用此豁免。
- 渲染后：按块检查各字段是否按顺序出现，单列主题装饰；表格展开为带列名的字段，重复列名属于模板呈现。原文图片alt作为属性检查，不要求变成可见说明。
- 输出文字核对.json与检查记录.json。未提供来源不能显示passed。基础导入器无法可靠处理的语法必须拒绝或走人工无损整理；不支持的内容不得静默丢失。
- 这些检查不证明Word/PDF已完整提取，也不证明微信粘贴后样式保留。仍需按SKILL.md做浏览器检查并如实说明微信实贴范围。
